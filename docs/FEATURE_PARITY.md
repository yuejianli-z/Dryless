# Dryless 双平台功能合同 · F2

确定日期：2026-09-13。Windows 侧负责定义共同产品逻辑，双方分别实现、验证。
本文件是目标行为，不是“已经实现”的声明；现状与缺口见 [MAC_REVIEW.md](MAC_REVIEW.md)。
覆盖此前 F1 合同。此次先同步功能定义与交接；用户随后要求统一20分钟，Windows计时/文案同步修改。其余缺口仍待实施，不合并main。

## 1. 产品与模块边界

Dryless 在本机检测眨眼，在持续未眨眼时给予递进提示，并在长时间连续在场后提醒微休息。
产品固定文案：**Blink more, dry less**；中文：**多眨一眼，少一分干涩**。
品牌名称、现有详细人眼 Logo 保留。状态图标的睁眼/闭眼只表达工作状态，不替换品牌资产。

| 模块 | 对用户负责的功能 |
| --- | --- |
| 摄像头与会话 | 真正开始/关闭摄像头、权限与故障恢复、会话开始/结束 |
| 眨眼检测 | 有效识别、校准、闭合再睁开计一次、丢脸恢复 |
| 眨眼提醒 | 三档递进、暂停/恢复、静音、声音与屏幕提示协调 |
| 微休息 | 连续在场计时、单次提示、结束后恢复眨眼提醒 |
| 后台驻留 | Windows 托盘 / Mac 菜单栏，共用主窗口的控制状态 |
| 当前记录 | 本次计数、运行时长、最近分钟数据、明确的等待/无数据状态 |
| 历史统计 | 时间范围、日周月聚合、真实平均、记录覆盖、CSV |
| 护眼内容 | 简短、可执行、有出处的 tips，不生成健康分数 |
| 设置与数据 | 本地保存、双语、兼容旧数据、音色与参数生效规则 |
| 交付 | 两端相同功能验收、各自真机验证、同版本发布 |

首页、统计、设置保持三页的信息分工。此合同不规定控件坐标、卡片样式、原生窗口或字体。
Mac 可保留 SwiftUI 原生风格，Windows 保留已认可的绿色界面；不得通过删功能获得原生感。
既有“不用首页折线图”“不恢复每日表格”“不出现本次详情弹窗”等明确用户决定仍有效。
前台应用分类、游戏/炒股场景归因、云同步、账号、健康诊断不在本版范围内。

## 2. 三个操作必须分开

| 操作 | 摄像头占用 | 检测和计数 | 眨眼/微休息自动提示 | 预览 |
| --- | --- | --- | --- | --- |
| 隐藏预览 | 继续 | 继续 | 按当前开关继续 | 隐藏 |
| 暂停提醒 | 继续 | 继续 | 全部暂停；取消当前提示/声音 | 保持原设置 |
| 关闭摄像头 | 释放 | 停止 | 全部停止；计时清零 | 立即清除旧帧 |
| 关闭声音 | 继续 | 继续 | 只停自动声音，屏幕提示保留 | 保持原设置 |

“暂停提醒”不能叫“关闭摄像头”，也不能偷偷停止统计。音色试听是用户主动操作，允许静音下试听；
开始试听本身不打开摄像头、不修改静音开关、不计提醒次数。暂停提醒时取消正在播放的试听。
进入摄像头关闭状态取消所有当前声音；关闭后用户仍可在设置里主动试听。

### 摄像头生命周期

状态：`off → starting → running → stopping → off`，另有 `error` 和系统 `suspended`。
- 首次安装保持关闭，点击“开启摄像头”才请求权限。记住用户最后一次明确的开启/关闭选择；
  之后启动应用按该选择恢复。已升级的旧版本未保存该字段时先保持关闭，并明确显示可开启。
- `starting` 允许取消；取消后权限回调、旧帧、旧线程完成事件不得重新打开设备。
- `stopping` 立即停止接受帧/统计/提醒、清除预览；设备释放确认后才能显示“已关闭”。
  释放期间不能并行创建第二个摄像头会话，也不能用强杀工作线程掩盖未释放。
- 主按钮、托盘、快捷操作走同一个控制器；快速连点、多个窗口不能产生多份采集/计时器。
- 新一次开启重新校准，开始新的本次会话；本次眨眼/提醒计数及分钟节律清零，历史保留。
- 关闭时保留最后一次会话的数值摘要并明确“本次已结束”，不能让计时继续走。
- 权限拒绝、无摄像头、被占用、拔出、检测失败显示各自原因和重试入口，不能显示“监测正常”。
- 锁屏/系统睡眠暂停采集和自动提示，不把这段时间计入记录或连续在场；唤醒/解锁后仅在
  用户此前选择开启时重连并重新校准。用户明确关闭后绝不能因唤醒、换语言、切页面而打开。
- 分辨率更改保存后在下次开启摄像头生效；界面显示实际协商分辨率，不能把未应用的值说成已应用。

### 系统驻留

- 主窗口关闭按钮：有可用托盘/菜单栏时隐藏窗口并继续原工作状态；首次说明一次仍在后台。
  没有可用驻留入口时正常退出，不能留下无法找回的隐藏进程。最小化遵循系统行为。
- 菜单：打开 Dryless、开启/关闭摄像头、暂停/恢复提醒、声音开关、退出。
  摄像头关闭时暂停项不可用但保留用户暂停偏好；再次开启不暗中取消该偏好。
- “退出”：停止所有音频、采集与后台任务，完成安全写入，释放摄像头，再结束进程。
- 状态图标：采集运行为睁眼；用户关闭/系统挂起为闭眼；暂停提醒是暂停标记，不能假装镜头关闭；
  无人脸与摄像头关闭必须区分。错误、正在连接/关闭也须有对应状态说明，不能只靠颜色。
- 托盘图标的闭眼是功能状态变体；桌面快捷方式及应用品牌 Logo 保持已批准版本。

## 3. 检测事件与当前会话

业务层接收统一事件：单调时间、摄像头状态、是否有人脸、眼部测量是否有效/已校准、是否眨眼。
Windows 的 MediaPipe 与 Mac 的 Vision 可以是不同适配器；提醒、统计不能散落在视图中各自计算。
两种模型输出不天然等价，Mac 必须用自己的真机验证精度。禁止把 Swift 测试通过说成模型精度一致。

- 一次可靠的“闭合 → 重新睁开”计一次；持续闭眼不得重复计数。
- 未校准、无有效眼部数据、丢脸、摄像头关闭期间不发送眨眼提醒，也不伪造零频率。
- 丢脸后重新识别，从重新有效识别开始等待首次提醒，不补发离开期间的提醒。
- 用单调时间计提醒/在场时长；系统日期变化只影响历史日期显示，不能引发提醒风暴。
- 本次运行时长指当前摄像头会话的采集时间；有效识别时长与其分开。不是应用进程存活时长。
- 最近窗口为 15/30/60 分钟及自动窗口；每个完整分钟的有效眼部识别少于 30 秒时显示缺测。
  有效分钟频率 = 该分钟的眨眼数 × 60 / 有效识别秒数；窗口平均按有效秒数加权。
  尚未完成一分钟时显示“等待有效记录”。不得混合累计频率与瞬时频率再截断到 30。

## 4. 三档眨眼提醒与音频

默认首次延迟 T=8 秒，递进间隔 I=5 秒。仅三个等级：首次、再次、加强。
持续未眨眼：T 首次，T+I 再次，T+2I 加强，之后每隔 I 重复加强；没有第四档。
例：8/13/18/23/28 秒的等级为 1/2/3/3/3。

- 检测到眨眼、丢失有效识别、暂停、关闭摄像头时，取消正在播放的眨眼声音及屏幕提示。
- 恢复有效检测/恢复提醒/微休息结束后，重新等待完整 T，不追补错过的档位。
- 修改 T 或 I：立即保存并开启新的等待周期，不基于旧时间突然补播多次。
- 提醒次数按“产生一次应提醒事件”计，包括加强档的后续重复；静音时照常计数。
  试听、音频重试、微休息不计入眨眼提醒次数，避免不同平台/音量设置改变统计。
- 固定四套已选音色：Polite（65）、Sharp（79）、Original（最初原版）、Blip。
  使用 `release-assets.json` 指定的同一组三档音频；不能另用系统 Ping/Glass 或一叫一次二叫两次代替。
- 一键试听三档，前一段结束后停 0.8 秒再播下一段。可以停止；再次点试听重启该组。
  换音色、离开设置/声音区域或退出时取消旧试听，不重叠。
- 单一可取消音频通道：微休息 > 主动试听 > 眨眼。优先级抢占取消旧播放，
  低优先级事件不排队；一个被跳过的提示不会在稍后突然补播。
- 自动声音遵守总声音开关。播放失败不让检测退出；显示声音不可用，屏幕提醒继续。
- 屏幕提示不抢焦点、不遮摄像头核心内容、不制造多个窗口；应用在后台时仍应能看见
  非激活提示。用户收起本轮眨眼横条后，本轮不反复展开；下一次眨眼后重新允许。

## 5. 微休息

沿用用户已确定的逻辑，无设置页开关/时长选择、无音色选择。
- 摄像头运行且持续检测到人在场，累计 20 分钟有效在场时间触发一次。
  “在场”不是“盯着屏幕”的证据，文案不得推断正在办公/游戏或保证完成了休息。
- 丢脸不超过 5 秒保留此前累计，但丢失时长不计入；超过 5 秒或采集时间跳变超过 5 秒清零。
  关闭摄像头、暂停提醒、睡眠/锁屏都清零，下一周期重新计算。
- 开始时播放固定“微休息开始”一次，并显示“已连续在场 20 分钟，起来活动一下吧”。
  静音只停声音，文字保留；不要每帧重复播放，也不要变成三档微休息。
- 提示最长 30 秒；连续离开画面 20 秒可提前结束。到时结束也不声称用户已休息。
- 提示期间停止眨眼声音/横条，眨眼检测和数值记录仍继续。
  结束后在場计时从零开始；眨眼重新等待 T 秒。无补发、无第四档、无抢占循环。

## 6. 历史、聚合与导出

0.2.0 沿用已确认的“保存分钟记录”历史口径，**不悄悄把旧记录换算成有效监测时长**。
首页近期有效识别频率与历史记录平均不是同一分母，必须各自明确说明。

- 日期范围：近 30 个日历日（含今日）、整年（当前 1/1—12/31）、全部历史、自选闭区间。
- 粒度：单日可看小时；日、周、月、自动。周以周一开始，月以每月一日开始。
  自动规则：单日→小时；2–45 天→日；46–210 天→周；211 天及以上→月。
  范围边缘只算选中部分，标记部分周期。不同粒度不能改变该日期范围的总数。
- 核心输出：总眨眼、保存分钟数/记录时长、有记录天数、记录平均频率。
  记录平均 = 所选记录总眨眼 / 所选记录条数；日/周/月平均按分钟数加权，不能平均每日平均。
- 原始记录为 0 次必须保留；无记录为 null/缺测；不能删掉 0 后再算平均或制造健康分数。
- 新采集必须先完成旧桶再归属新事件，按桶开始的当地日期/时间保存；跨午夜不可记错一天。
  不因停机/暂停回调堆积而把没有采集的时间写成 0 次眨眼。真正采集但无人脸的分钟需保留
  缺测标记，不能用于新记录平均。已有旧数据无法推断有效性，按原记录保留并披露口径。
- 新记录增加可选 `valid_seconds`、`session_id`、`bucket_start` 元数据；新缺测记录以
  `blinks: null` 与 `missing_reason` 表达并排除计数分母。旧记录没有字段时不得补造有效秒数。
  两端读写器同时升级；此前不存在的字段使用默认值，不能因新增一个字段丢掉整份旧设置。
- 从任何图形都应能取得某一时间段的记录时长、频率、总数、覆盖天数及是否为部分周期。
  时间气泡图保留这些语义；每日长表与虚构健康评分不恢复。
- 红→黄→绿表达频率由低到高，不能将更高频率宣称更健康。
  15–20 一般参考带固定；本期真实平均从记录计算，单独标记；0 条记录就没有平均线。
- 导出所选日期范围的逐分钟记录，含真实 0、标记的缺测及统计所需字段；不是图上几个汇总点。
  日期、有效记录计数和总数可由 CSV 复算。取消导出不写文件；写入失败明确提示且保留旧文件。
- 旧 Windows `days` / 单日 `date+history` 和现有 Mac `records` 格式提供明确读取/迁移器。
  原始文件先备份；同一次迁移只能执行一次；无法解析不能静默显示空白并覆盖原文件。
- 本地日期与时间区分：新数据记录带时区的时间戳和本地桶日期，夏令时重复小时不覆盖记录。
  旧数据缺乏时区不强行纠正。换语言不重新解释日期、数字或改变统计范围。

## 7. 护眼 tips 与文案

固定内容清单，不用模型实时生成健康建议；主界面一次显示一个简短提示，可手动换一条。
若做自动轮播，间隔至少 20 秒、鼠标悬停/键盘焦点在该区域时暂停；活动提醒期间不轮换抢注意力。
tips 没有声音、不单独弹窗、不改计时器。不是任务，更不需要“完成”打卡。

| 内容 ID | 中文 | English |
| --- | --- | --- |
| blink | 看屏幕时，记得自然眨眼。 | Remember to blink naturally while using your screen. |
| distance | 每 20 分钟，看约 6 米远处至少 20 秒。 | Every 20 minutes, look about 20 feet away for at least 20 seconds. |
| glare | 调整屏幕亮度与位置，减少刺眼的反光。 | Adjust screen brightness and position to reduce glare. |
| air | 避免风扇或空调气流直接吹向眼睛。 | Keep direct airflow from fans or vents away from your eyes. |

内容依据：[Mayo Clinic, Eyestrain — self-care](https://www.mayoclinic.org/diseases-conditions/eyestrain/diagnosis-treatment/drc-20372403)。
“20-20-20”是一般用眼建议；产品同样在连续在场20分钟时提示。看远处20秒是建议的休息动作，
界面提示最多展示30秒是通知停留时间，两者不是不同的触发周期。
保留品牌 slogan；不推销药物，不把频率作为诊断或“健康程度”评分。
频率个体与任务差异可参考 [blink-pattern research](https://pubmed.ncbi.nlm.nih.gov/24413278/)，
一般频率说明参考 [exploratory blink study](https://pmc.ncbi.nlm.nih.gov/articles/PMC10001854/)。

## 8. 设置、语言与隐私

| 设置 | 默认与范围 | 生效 |
| --- | --- | --- |
| 首次提醒 | 8 秒；5–60，步长 1 | 保存后新计时周期 |
| 递进间隔 | 5 秒；3–30，步长 1 | 保存后新计时周期 |
| 音色 | Blip；四个既定方案 | 取消旧试听，下次提示使用新音色 |
| 声音 | 开 | 关闭立即停自动声音；屏幕提示保留 |
| 分辨率 | 640×480；另有 1280×720、1920×1080 | 下次开启摄像头，披露实际结果 |
| 检测阈值 | 0.60；0.40–0.80，步长 0.05，显示两位小数 | 新检测样本；阈值变更后重校准，避免误计眨眼 |
| 处理间隔 | 每 2 帧；1–5，步长 1 | 新检测样本 |
| 语言 | 中/英 | 立即；Language 名称恒定 |
| 预览可见 | 开 | 立即；保存偏好；不影响摄像头 |

以前保存的范围外参数不静默改写；若不能支持，应说明并要求选择合法值。存储失败不得显示“已保存”。
摄像头开启偏好、声音、音色、参数、语言、预览偏好保存在本机；暂停提醒是当前应用会话状态，
关闭/开启镜头时保留，退出应用后恢复正常提醒。微休息累计/未发提醒不跨重启保存。
不存相片/视频/生物特征模板，不上传相机数据；只写设置和必要的数值历史。
尚不做前台应用、窗口标题或其他软件活动收集；若以后引入，另定明确可关闭的授权规则。

## 9. 状态优先级与共同验收

呈现一个主状态：退出/关闭中 > 设备错误 > 摄像头关闭/系统挂起 > 启动中 > 提醒已暂停 >
微休息提示 > 无人脸/校准 > 眨眼提示 > 监测中。设备/检测状态也可作为独立次要信息，不能相互矛盾。
只有 camera=running 且眼部有效、提醒未暂停、微休息未激活才允许产生眨眼提醒。

| 验收 ID | 操作或输入 | 必须结果 |
| --- | --- | --- |
| CAM-01 | 首次启动；点击开启；再关闭 | 首次无占用；开启后请求/采集；关闭后设备释放，旧帧清除 |
| CAM-02 | 许可请求未返回就取消；随后允许 | 仍保持关闭，不因迟到回调启动 |
